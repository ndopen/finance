# ezBookkeeping 迁移至 FastAPI 完整开发计划

## 项目概述

### 当前情况分析

**当前 FastAPI 项目特点：**
- 基础的 FastAPI 框架 + SQLModel + PostgreSQL
- 简单的用户认证系统（JWT）
- 基础的 CRUD 操作（用户、项目）
- 使用 Alembic 进行数据库迁移
- 前端使用 Vue 3 + TypeScript + Vite

**目标 ezBookkeeping Go 项目特点：**
- 完整的个人财务管理系统
- 丰富的功能模块：账户管理、交易记录、分类标签、报表分析等
- 支持多语言、多货币、时区
- AI 功能集成（图像识别、MCP 协议）
- 完善的导入导出功能
- 移动端 PWA 支持

## 技术栈对比分析

| 方面 | 当前 FastAPI 项目 | ezBookkeeping Go 项目 |
|------|------------------|---------------------|
| **后端语言** | Python (FastAPI) | Go (Gin/Echo) |

## API 接口迁移方案

### 当前 API 结构
```
/api/v1/
├── login/
├── users/
├── items/
└── utils/
```

### 目标 API 结构（参考 ezBookkeeping）
```
/api/v1/
├── tokens/          # 认证相关
├── users/           # 用户管理
├── accounts/        # 账户管理
├── transaction/
│   ├── categories/  # 交易分类
│   ├── tags/       # 交易标签
│   └── transactions/ # 交易记录
├── exchange-rates/  # 汇率管理
├── import/         # 数据导入
├── export/         # 数据导出
└── settings/       # 用户设置
```

### API 响应格式标准化

**成功响应：**
```json
{
    "result": {...},
    "success": true
}
```

**失败响应：**
```json
{
    "errorCode": 10001,
    "errorMessage": "Error description",
    "path": "/api/v1/xxx",
    "success": false
}
```

## 数据库设计方案

### 主要数据表结构

#### 1. 用户相关表
- `users` - 用户基础信息
- `user_sessions` - 用户会话
- `user_two_factor_settings` - 2FA 设置
- `user_settings` - 用户偏好设置

#### 2. 财务核心表
- `accounts` - 账户信息
- `transaction_categories` - 交易分类
- `transaction_tags` - 交易标签
- `transactions` - 交易记录
- `transaction_pictures` - 交易图片

#### 3. 系统支持表
- `exchange_rates` - 汇率信息
- `currencies` - 货币信息
- `import_templates` - 导入模板

### 数据库迁移策略
1. 使用 Alembic 管理数据库版本
2. 保持向后兼容性
3. 分阶段迁移，先创建新表，再迁移数据
4. 提供数据回滚方案
